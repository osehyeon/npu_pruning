## 결론

`yolov3` 라는 이름을 달고 있는 파일들이 **서로 다른 세 모델**입니다.
아키텍처는 같고(Conv 75개 · 총 채널 27,069) **가중치가 무관**합니다.

첫 Conv `(32,3,3,3)` 의 가중치 표준편차로 구분됩니다 — 이 레이어는 각 모델에 유일해서
짝짓기 오류 없이 비교할 수 있습니다.

| std | 계열 | 대표 파일 | 내보내기 특징 |
|---:|---|---|---|
| **6.145** | ultralytics YOLOv3 | `yolov3/yolov3.onnx` · `yolo_val/yolov3_608_ultralytics.onnx` | pytorch · opset 17 · 입력 `images` · **출력 1개**(검출 헤드 융합) |
| **3.629** | **Nota 학습 PyTorch YOLOv3** (프루닝의 부모) | `demo_pruning/model_float32/yolov3.onnx` → **`workspace_docs/model/yolov3_original_fp32.onnx`** | pytorch 1.13 · opset 12 · 입력 `input.1` · **LeakyRelu** · 출력 3개(raw 헤드) |
| **1.470** | **mmdetection `yolov3_d53_mstrain-608_273e_coco`** | **`demo_1127/yolov3/...neubla_u8_lwq_movingaverage.onnx`** (배포 uint8) | `onnx.quantize` · opset 12 · 입력 `input` · 후처리 내장 |

서로의 상관계수는 **−0.05 ~ +0.14** 로 사실상 무관합니다.
가중치뿐 아니라 **내보내기 도구·opset·입력 이름·출력 개수까지 전부 다릅니다.**

### 출처 확정 — ONNX Model Zoo `yolov3-12` 입니다 (2026-08-26)

`yolov3_original_fp32.onnx` 는 Model Zoo `yolov3-12` 에서 **BatchNorm 을 Conv 에
접어 넣은 것**입니다. Conv 75 개 전부 **최대 오차 0.000e+00**, 비트 단위 완전 일치입니다.

```
zoo yolov3-12    Conv 75 · BN 별도 · 연산자 25종 · NMS 내장 · 247.9 MB
이 파일          Conv 75 · BN 접힘 · 연산자  5종 · raw 헤드 3개 · 247.7 MB
```

접기 공식은 채널마다 `W' = W · gamma / sqrt(var + eps)` 입니다.

**한때 "Model Zoo 가 아니다" 라고 정정했는데 그 정정이 틀렸습니다.** 근거 둘이 모두
성립하지 않습니다.

- 가중치를 **BN 을 접지 않고** 대조했습니다. 접지 않으면 채널 배율 때문에 상관이
  0.60 으로 떨어집니다. 접으면 1.0000 입니다.
- mAP 비교의 조건이 달랐습니다. 공표값 28.74 는 **416px · score 0.6** 이고
  우리 38.26 은 **608px · score 0.001** 이며 게다가 **오염된 val2017** 값입니다.
  깨끗한 5k 로 재면 31.51 로 문헌 대역입니다.

그래프 구조가 다른 것은 맞지만 가중치는 같은 파일에서 왔습니다.

**따라서 계보는 Darknet 입니다.** Model Zoo `yolov3-12` 가 pjreddie 가중치 변환본이므로
학습 분할이 `trainvalno5k` 이고, held-out 이 `5k` 입니다. 이것이
[coco-split-contamination.md](./coco-split-contamination.md) 의 관측과 정확히 맞습니다.

재현:

```bash
python - <<'EOF'
# zoo 의 Conv 뒤 BatchNormalization 을 찾아 W 에 접고 우리 파일과 대조
EOF
```

`paper/evidence` 묶음의 `07-docs` 와 함께 보십시오.

## 무엇이 잘못될 수 있나

### ✗ 잘못된 비교 — 실제로 제가 했던 실수

```
배포 원본 uint8 (mmdet 계열)      AP 28.92
   vs
workspace_docs/model/*_fp32.onnx (Nota 학습 계열)  AP 38.26
   → "양자화 손실 −9.34"  ← 서로 다른 모델을 비교한 것. 무의미
```

이 오해 때문에 *"압축 모델이 양자화에 견고하다"* 는 결론을 두 차례 냈다가 모두 철회했습니다.

### ✓ 올바른 비교

| 비교 | 유효한가 | 근거 |
|---|---|---|
| `yolov3_original_fp32` ↔ `yolov3_pruned40/50_fp32` | **✓ 유효** | 미절단 레이어 가중치 상관 **1.0000** — 같은 계보 |
| 배포 `40.onnx` ↔ 제 재양자화 `pruned40_u8_maD20` | **✓ 유효** | 가중치 **완전 동일**(상관 1.000000, 상대오차 0.000%) |
| 배포 원본 u8 ↔ `yolov3_original_fp32` | **✗ 무효** | 다른 모델 |
| 배포 원본 u8 ↔ 배포 `40.onnx` | **✗ 무효** | 다른 계보끼리의 비교 |

**프루닝 모델(40 %/50 %)은 Nota 학습 계열에서 파생**되었습니다.
따라서 프루닝 손실을 볼 때의 기준은 반드시 `yolov3_original_fp32.onnx` 입니다.

### 세부 — 가중치는 재현되지만 활성화 스케일은 재현되지 않습니다

배포 프루닝 모델과 제 재양자화본을 QLinearConv 75개 전부 대조하면:

| 항목 | 40 % | 50 % |
|---|---|---|
| 가중치 상관 (최소) | **1.000000** | **1.000000** |
| 가중치 상대오차 | **0.000 %** | **0.000 %** |
| 가중치 스케일비 | 1.0000 (전 구간) | 1.0000 (전 구간) |
| 출력 활성화 스케일비 | 평균 1.002 · 범위 **[0.59, 1.49]** | 평균 0.996 · 범위 **[0.57, 1.47]** |
| 활성화 스케일 5 % 이내 일치 | 34.7 % | 34.7 % |

**가중치 양자화는 결정론적이라 완전히 재현**되지만,
**활성화 스케일은 캘리브레이션 이미지에 의존**해 최대 ±50 % 까지 벌어집니다.
그런데도 AP 차이는 작습니다 — 활성화 스케일이 이 모델에서는 둔감하다는 뜻입니다.

실무적 함의: 배포 파일로 잰 NPU 수치와 제 재양자화본으로 잰 CPU 수치를
**섞어서 한 표에 넣으면 안 됩니다.** 같은 파일로 잰 값끼리만 비교하세요.

## 어떻게 확인했나

```python
# 첫 Conv 는 (32,3,3,3) 로 각 모델에 유일 — 짝짓기 확실
배포 u8 를 역양자화:  std 1.4699   범위 [−9.31, +11.70]
fp32 원본:            std 3.6289   범위 [−19.36, +22.40]
상관계수 −0.0527
```

역양자화 방법 자체는 정확합니다 — 같은 방법으로 배포 `40.onnx` 와
제 재양자화 모델을 비교하면 **오차 0.36 %** 로 일치합니다.

워크스페이스의 fp32 파일 전수 조사에서도 배포 uint8 과 맞는 것이 **없었습니다**
(최고 상관 0.14). **배포 원본의 fp32 소스는 이 워크스페이스에 없습니다.**

### 부수 효과 — 활성화 스케일 차이도 설명됩니다

배포 모델의 활성화 스케일이 제 재현보다 일관되게 **0.43배**(약 1/2.3) 좁았는데,
가중치 크기 비율(3.63 / 1.47 = **2.47배**)과 맞아떨어집니다.
캘리브레이션 설정 문제가 아니라 **애초에 값의 스케일이 다른 모델**이었습니다.

## 논문 절대값 수수께끼도 이걸로 설명됩니다

`pruning-map-comparison.md` 에 *"원본 AP 38.26 이 논문 33.7 보다 4.6점 높다 — 원인 미규명"*
이라고 적어두었는데, **애초에 다른 모델이었습니다.**

```
mmdet yolov3_d53_mstrain-608_273e_coco   공표 33.7 (val2017 fp32)
   → 배포 uint8 은 28.92 — 양자화 손실 감안하면 타당

Nota 학습 YOLOv3 (제 fp32)                38.26
   → mmdet 수치와 비교할 이유가 없음
```

**33.7 과 대조해야 할 대상은 제 fp32 가 아니라 배포 모델의 fp32 소스**이고,
그 파일은 워크스페이스에 없습니다.

### 계보 확인 — Neubla 자체 검증 자료로 대조했습니다

`yolo_val/` 은 Neubla 가 **ultralytics `val.py`** 로 돌린 검증 환경이고,
`runs/val/exp14/` 에 그 예측 JSON(5,000장)이 남아 있습니다.
그 모델은 **제 fp32 원본과 같은 계보**입니다:

| 파일 | 첫 Conv std | fp32 원본과의 상관 |
|---|---:|---:|
| `demo_pruning/model_float32/yolov3.onnx` (= 제 fp32 원본) | 3.6289 | 기준 |
| `yolo_val/yolov3-mod-precomile-quantize.onnx` | 3.6268 | **+0.9999** ✓ |
| `yolo_val/yolov3_608_neubla.onnx` | 1.4699 | −0.0527 ✗ |
| `demo_1127/...movingaverage.onnx` (배포 원본) | 1.4699 | −0.0527 ✗ |

이 uint8 모델을 **양쪽 파이프라인으로 모두** 재서 변수를 분리했습니다 (전부 5,000장):

```
① 원본 fp32   · 제 파이프라인(cv2.resize)               38.26
② 원본 u8(Neubla 양자화) · 제 파이프라인                36.21
③ 원본 u8(내 재양자화)   · 제 파이프라인                35.87
④ 원본 u8(Neubla 양자화) · ultralytics(letterbox)       38.14

  양자화 방법 차이     ② − ③ = 0.34   거의 없음
  평가 파이프라인 차이 ④ − ② = 1.93   letterbox 가 유리
  양자화 손실          ① − ② = 2.05
```

> ⚠️ **정정** — 앞서 *"38.14 와 38.26 이 0.12 차이라 파이프라인이 검증됐다"* 고 적었는데,
> ④(uint8)와 ①(fp32)을 비교한 것이라 성립하지 않습니다. 두 오차가 우연히 상쇄된 것입니다.
> 실제로는 **제 절대값이 표준(letterbox) 대비 약 1.9 낮습니다.**
> 표준 방식으로 재면 원본 fp32 는 약 **40.2** 로 추정됩니다.
> 모든 모델이 같은 파이프라인을 타므로 **상대 비교는 영향받지 않습니다.**

> 부수 확인: `yolo_val/yolov3_608_neubla.onnx` 는 배포 원본과 **동일한 mmdet 계열**입니다.
> 그 모델의 `exp4` 실행은 AP 0.71 로 실패한 기록입니다(디코더 불일치로 추정).

### 결론 — "절대값 불일치" 는 해소되었습니다

```
33.7  = mmdet yolov3_d53_mstrain-608_273e_coco 의 공표값
         → 배포 원본 uint8(28.92) 이 대조할 대상

38.3 (제 파이프라인) / 약 40.2 (표준 letterbox) = Nota 학습 YOLOv3 의 성능
         → 제 fp32 원본과 프루닝 모델들이 속한 계열
         → 같은 계보 uint8 을 Neubla 가 38.14 로 측정 (letterbox 기준)
```

애초에 **두 수치를 비교할 이유가 없었습니다.** 서로 다른 모델의 성적표입니다.

## 실무 지침

1. **파일명을 믿지 마세요.** `yolov3.onnx` 가 셋 다 다른 모델입니다.
2. **비교 전에 계보를 확인하세요** — 첫 Conv `(32,3,3,3)` 의 std 로 30초면 구분됩니다:

```python
import onnx, numpy as np
from onnx import numpy_helper
m = onnx.load(path); init = {i.name: i for i in m.graph.initializer}
for n in m.graph.node:
    if n.op_type == "Conv" and n.input[1] in init:
        w = numpy_helper.to_array(init[n.input[1]])
        if w.shape == (32, 3, 3, 3):
            print(f"std {w.std():.4f}")   # 6.145 / 3.629 / 1.470
            break
```

3. **프루닝 실험의 기준은 `workspace_docs/model/yolov3_original_fp32.onnx`** 입니다
   (Nota 학습 계열, 프루닝 모델의 실제 부모).
4. **배포 원본 uint8 은 별개 모델**로 취급하고, 프루닝 손실 계산에 쓰지 마세요.
