## 0. 08-11~12 신규 결과 (요약)

### 0.1 staircase 논거를 우리 실측으로 확보 ★

`dbgprint` OFF · `maD20` 양자화 · `lw` 컴파일 · 50 % 프루닝 4종:

| sc | raw MACs (G) | padded MACs (G) | 바이너리 | **NPU (ms)** |
|---:|---:|---:|---:|---:|
| 8 | **38.2** | 61.9 | 112 MB | 48.5 |
| 16 | 38.1 | 60.2 | 111 MB | 48.5 |
| 32 | 39.0 | 59.2 | 109 MB | 48.4 |
| **64** | **42.0** | **58.9** | **105 MB** | **43.5** |

**sc64 는 raw MACs 최다인데 최속.** 2025-03 원 측정과 개선폭이 일치합니다
(10.6 % ↔ 10.2 %). 인용값이 아니라 우리 측정으로 §4 가 섭니다.

→ `docs/npu-measurement-pitfalls.md` §3

### 0.2 `dbgprint` 교란 — 기존 NPU 수치 전부 무효

보드 펌웨어의 UART 디버그 출력이 **모델 무관 약 31 ms 고정 오버헤드**로 붙어
**가속 배수를 희석**하고 있었습니다.

| | ON (기존) | **OFF** |
|---|---:|---:|
| 원본 / 40 % / 50 % (`lw`) | 90.5 / 76.4 / 74.8 ms | **58.3 / 44.8 / 43.1 ms** |
| 가속 배수 | 1.18× / 1.21× | **1.30× / 1.35×** |

`o_dbg`(호스트 드라이버)와 **별개**이며 문서에 없던 항목입니다.
보드 재부팅 시 기본값(ON)으로 복귀합니다.

### 0.3 우리 프루닝 재현 + 재학습 완료 — 무손실 확인

원 저자 분할 그대로(`trainvalno5k.part` 117,264장 · `5k.part` 5,000장, 해시 고정),
RTX 5090 에서 10 에포크:

| 모델 | AP | AP50 | AP75 |
|---|---:|---:|---:|
| 원본 (Darknet) | 31.51 | 56.18 | 31.93 |
| **40 % 프루닝 + 재학습** | **32.50** | 52.30 | 35.20 |

**학습 데이터가 원본과 동일**하므로 교란이 없습니다. 5,000장 부트스트랩 95 % 구간
폭이 1.03(±0.5)이므로 **무손실로 읽는 것이 안전**합니다.

프루닝 직후(재학습 없음)는 **AP 0.03** — 재학습이 성능의 거의 전부를 만듭니다.

### 0.4 `egs` 컴파일 옵션

50 %/sc64 기준 `lw` 43.5 ms → `egs` **22.3 ms (1.88×)**, 바이너리 105 → 92 MB.

비정렬 모델에서 `egs` 컴파일이 실패했으나 **원인을 분리하지 못했습니다**
(해당 모델들이 재학습 전이라 유효 출력 없음). 논문에서는 §한계 한 줄로만.

## 1. 논문 방향 — 두 가지 선택지

조사 결과 원래 계획했던 *"YOLOv3 압축의 속도–정확도 트레이드오프"* 는 **핵심 수치가 흔들렸고**,
대신 **평가 방법론 쪽에 훨씬 단단한 결과**가 생겼습니다.

### (A) 평가 방법론 중심 — 권장

> **압축 모델 평가에서 데이터 분할과 검출 예산이 결론을 뒤집는다: YOLOv3–NPU 사례연구**

기여가 전부 실측으로 뒷받침되고, 오염 문제의 영향을 받지 않습니다.
"우리 압축이 우수하다"가 아니라 "압축 평가가 이렇게 틀릴 수 있다"는 주장이라
baseline 절대값 논쟁에서 자유롭습니다.

### (B) 원래 계획 — 트레이드오프 중심

> **YOLOv3 구조적 프루닝 + INT8 양자화의 NPU 실측 트레이드오프**

핵심 수치(프루닝 손실)가 현재 **643장 소표본**에만 근거합니다.
GPU 재학습으로 깨끗한 5,000장 비교를 확보한 뒤에야 성립합니다.

**(A)로 쓰고 (B)를 §결과의 한 절로 넣는 구성**이 현재 재료에 맞습니다.

## 2. 확정된 결과 (전부 실측·재현 가능)

### 2.1 평가셋 오염이 프루닝 손실의 부호를 바꾼다 ★ 핵심

원본(Darknet)과 프루닝본(Nota 재학습)의 held-out 집합이 어긋나 있습니다.

```
원본      학습 trainvalno5k = train2014 + val2014 − 5k(pjreddie)
프루닝본   학습 train2017    = train2014 + val2014 − val2017
5k ∩ val2017 = 643장  (무작위 기대 겹침 617)
→ val2017 의 87.1 %가 원본의 학습 데이터
```

같은 세 모델·같은 코드·같은 전처리, 데이터만 교체:

| 평가 집합 | original | pruned40 | pruned50 | **Δ40** | **Δ50** |
|---|---:|---:|---:|---:|---:|
| val2017 5,000 *(원본만 오염)* | 38.26 | 30.19 | 26.13 | **−8.07** | **−12.13** |
| **643 교집합** *(양쪽 깨끗)* | **34.16** | **32.20** | **29.21** | **−1.95** | **−4.94** |
| 5k 5,000 *(프루닝본만 오염)* | 31.51 | 40.36 | 36.11 | **+8.85** | **+4.60** |

**진폭 16.9점, 부호까지 뒤집힘.** 세 표 전부 "COCO 전수 · 표준 프로토콜"이라 적을 수 있습니다.

외부 정합: 깨끗한 5k 에서 원본 31.51 ↔ 문헌 33.0(논문) / 33.1(ultralytics) / 32.9(우리 재현).

→ `docs/coco-split-contamination.md`, `example/eval_map_split.py`

### 2.2 검출 예산 미기재가 절대값을 9.18점 움직인다

동일 모델·동일 분할(val2017 5,000), 예산만 변경:

| 검출 예산 | AP | AP50 | AP75 | APs |
|---|---:|---:|---:|---:|
| score 0.6 · max 20/클래스 *(배포 그래프 기본값)* | 31.55 | 50.43 | 35.60 | 16.40 |
| score 0.001 · maxDets 100 *(표준 COCO)* | **40.73** | 70.68 | 42.53 | 27.47 |
| | **+9.18** | +20.3 | | **+67 %** |

작은 객체일수록 이득이 큽니다(APs +67 %) — 재현율 절단의 서명입니다.

**출처 추적**: ONNX Model Zoo `yolov3-12` 의 NMS 상수(`max 20 · IoU 0.5 · score 0.6`)는
`qqwweee/keras-yolo3` 의 `yolo_eval()` **함수 기본값**이 그래프에 굳은 것입니다.
모델 카드는 `maxDets=100` 이라 적고 있어 **실제 계산과 다릅니다.**

조사한 6개 출처(YOLOv4 · Gaussian YOLOv3 · ultralytics · PP-YOLO · YOLOX · ONNX Zoo)
**어느 곳도 검출 예산을 밝히지 않습니다.**

→ `example/eval_map_zoo.py`, `example/map_zoo_*.json`

### 2.3 staircase 는 연산량이 아니라 하드웨어 정렬 파라미터다

12개 스윕 모델(10/30/50 % × sc 8/16/32/64)의 연산량과 NPU 실측 대조:

| ratio | sc | raw MACs (G) | padded MACs (G) | 64배수 conv | NPU (s) |
|---:|---:|---:|---:|---:|---:|
| 50 | 8 | **38.0** | 61.7 | 18/75 | 0.0462 |
| 50 | 16 | 37.9 | 59.9 | 32/75 | 0.0463 |
| 50 | 32 | 38.7 | 58.9 | 52/75 | 0.0463 |
| **50** | **64** | **41.8** | **58.7** | **70/75** | **0.0413** |

`padded MACs = Σ ⌈Cout/64⌉·64 · ⌈Cin/64⌉·64 · k² · H · W`

```
raw MACs    ↔ NPU latency   r = +0.8952      (스윕 12종 + 원본)
padded MACs ↔ NPU latency   r = +0.9414
raw MACs    ↔ NPU latency   r = +0.8778      (스윕 12종만)
padded MACs ↔ NPU latency   r = +0.9319
```

**sc64 는 raw MACs 가 가장 많은데 NPU 에서 가장 빠릅니다.** 연산량 지표만 보면
정반대 결론이 나옵니다. `.o` 바이너리의 활성값 버퍼 분석과도 일치합니다.

한계: 30 % 구간에서 sc32(0.0466) < sc64(0.0474) 로 역전 — 정렬만으로 전부 설명되지는
않으며, 차이는 측정 오차(±1.3 ms) 안입니다.

→ `example/analyze_staircase_hw.py`, `staircase_hw.json`

### 2.4 재학습이 성능의 거의 전부를 만든다

| 단계 | AP (643 깨끗) |
|---|---:|
| 원본 | 34.16 |
| 프루닝 직후 (재학습 없음) | **0.03** |
| 프루닝 + 재학습 | 32.20 |

37 % 채널 제거는 망을 **완전히 파괴**하고(AP 0.03), 재학습이 전부를 복원합니다.
Nota 의 재학습 전 실물(250514)과 우리 재현본이 같은 거동(0.03 / 0.00)을 보여
프루닝 구현이 검증됩니다.

→ `example/prune_darknet.py`

### 2.5 계보 — 해시 수준으로 확정

```
pjreddie yolov3.weights (md5 c84e5b99…)
   │  qqwweee/keras-yolo3 → keras2onnx 1.5.1        ← Conv 75개 전부 비트 동일
   ▼                                                   (레이어 순열·BN eps 1e-3 차이만)
ONNX Model Zoo yolov3-12.onnx (sha256 d97d7d5c…)    ← 공식 배포본과 동일 확인
   │  BN fold · 후처리 절단 · 608 고정                ← 27,069채널 전부 |cos| = 1.000000
   ▼
yolov3.onnx (md5 c4964902…)  = 프루닝 부모
   │  L2 상위 k · 64 정렬 · residual 그룹 공유 마스크  ← |ΔW| = 0 으로 역복원
   ▼
compressed_yolov3_40%.onnx (md5 d26ca145…)
```

- BN epsilon 은 Keras 기본값 **1e-3**(Darknet 은 1e-5). 보정 시 AP 영향 **+0.13** — 무시 가능
- 프루닝 선택 기준: 독립 레이어 **25/25 가 L2 상위 k 와 정확히 일치**, L1 은 0/39
- 명목 40 % → **실효 37.12 %**, 잔여 채널 전부 64 배수

### 2.6 컴파일 옵션 `egs` 는 무손실

세 모델 쌍 모두 6개 지표가 소수점 둘째 자리까지 동일하고 속도만 **1.38~1.44×**.
동일 모델·동일 데이터 비교라 오염과 무관합니다.

### 2.7 NPU 속도

```
원본 90.5 ms · 40 % 76.4 ms (1.18×) · 50 % 74.8 ms (1.21×)
바이너리 166.8 MB → 103.9 MB (−38 %)
40 % → 50 % 는 속도 2.1 % 더 얻고 AP 를 더 내주는 거래
```

속도 측정은 오염과 무관하게 유효합니다.
