# 집필 계획 — 지금 쓸 수 있는 것과 없는 것

*2026-08-11 · 선행 논문(Sensors 2025, 25, 1376)의 후속*

## 논문 위치

```
선행    모델 고정 · 스케줄링 최적화 (더블 버퍼링 · 큐)   → 처리량 4.81×
본 논문  모델 압축 (구조적 프루닝) · NPU 정렬 인식        → 연산량·지연 축소
```

**핵심 주장 후보**: *staircase(채널 정렬)는 연산량이 아니라 하드웨어 타일 경계를
맞추는 파라미터이며, NPU 지연은 raw MACs 가 아니라 padded MACs 를 따른다.*

이것이 "NPU 를 위한 프루닝"이라는 논문의 기술적 중심이 된다.

## 1. 지금 쓸 수 있는 것 ✅

| # | 내용 | 근거 | 논문 위치 |
|---|---|---|---|
| A | **staircase = 하드웨어 64 정렬** — padded MACs 가 NPU 지연을 더 잘 설명 (r 0.921 대 0.881). sc64 는 raw MACs 최다인데 NPU 최속 | 12모델 실측 + 2025-03 NPU 스윕 | §4 핵심 |
| B | **명목 대 실효 감축률** — 명목 40 % → 실효 37.12 %, 잔여 채널 전부 64 배수, 앞단 26 conv 무손상 | manifest 19종 | §4 |
| C | **프루닝 기준 복원** — 독립 레이어 25/25 가 L2 상위 k 와 정확히 일치, L1 은 0/39. residual 그룹은 단일 마스크 공유 | \|ΔW\| = 0 역복원 | §4 |
| D | **재학습 필수성** — 프루닝 직후 AP 0.03 (완전 붕괴). Nota 실물과 우리 재현본 동일 거동 | 실측 | §5 |
| E | **양자화 손실 −1.57** (fp32 28.43 → uint8 26.86), CPU 2.8× 가속, 78 → 20.6 MB | 5k 전수, 동일 경로 | §5 |
| F | **모델 크기** 248 MB → 20.6 MB (−92 %) | — | §5 |
| G | **컴파일 옵션** LW/EGS × Single/Half | 선행 논문 Table 2 + 우리 egs 측정 | §4 배경 |
| H | **평가 프로토콜 정립** — 분할 해시 고정, 검출 예산 명시, 부트스트랩 ±0.5 | 실측 | §5.1 |
| I | **계보 확정** — pjreddie 가중치와 비트 동일, sha256 체인 | 실측 | §5.1 또는 부록 |
| J | **평가셋 오염 발견** — Darknet 계열을 val2017 로 평가하면 87 % 오염 | 실측 | §5.1 각주 또는 §6 |

**A~C 만으로 §4(방법론)가 완성된다.** NPU 하드웨어 특성과 프루닝 설계를 연결하는
논거가 전부 확보돼 있고 추가 측정이 필요 없다.

## 2. 지금 쓸 수 없는 것 ⬜

| # | 내용 | 왜 막혔나 |
|---|---|---|
| K | **프루닝의 정확도 손실 확정값** | 전처리에 따라 −3.08 / −0.40 으로 갈림 (§실험 2) |
| L | **"프루닝이 무손실"이라는 주장** | 재학습 레시피 교란 미통제 (§실험 1) |
| M | **우리 프루닝본의 NPU 지연·처리량** | **컴파일·실측 안 함** (§실험 3) ← 가장 치명적 |
| N | **NPU 정확도** | 기존 R 계열은 오염된 val2017 기준 (§실험 4) |
| O | **시스템 통합 성능 (FPS)** | 선행 논문 파이프라인에 미탑재 (§실험 5) |
| P | ratio × staircase 정확도 격자 | 조합별 재학습 필요 (§실험 7) |

**M 이 핵심 결손이다.** "NPU 개선 논문"인데 **우리가 만든 모델의 NPU 수치가 없다.**
현재 NPU 데이터는 (1) 2025-03 스윕 — 당시 컴파일 조건, (2) R 계열 — 정확도는 오염,
속도만 유효. 둘 다 우리 재현본이 아니다.

## 3. 해야 할 실험

우선순위는 **논문 성립 여부**를 기준으로 매겼다.

| # | 실험 | 자원 | 시간 | 필수? | 해소 항목 |
|---|---|---|---|:--:|---|
| 3 | **우리 프루닝본 nbc 컴파일 → NPU 지연 실측** | 보드 | 반나절 | **필수** | M |
| 1 | **통제: 원본을 동일 레시피로 10 epoch 재학습** | GPU | 5 h | **필수** | L, K |
| 2 | **전처리 통일 재측정** (원본·프루닝본 동일 조건) | CPU | 1 h | **필수** | K |
| 4 | NPU 정확도를 5k 로 재측정 | 보드 | 반나절 | 권장 | N |
| 5 | 선행 파이프라인에 탑재해 FPS 측정 | 보드 | 하루 | 권장 | O |
| 6 | 재학습 연장 (10 → 30 epoch) | GPU | 8 h | 선택 | 회복 포화 확인 |
| 7 | ratio × staircase 격자 재학습 | GPU ×N | 수일 | 선택 | P |

### 필수 셋의 근거

- **실험 3** — 없으면 NPU 논문이 아니다. 컴파일 도구(`nbc`)와 보드는 이미 있다
- **실험 1** — 없으면 프루닝 효과를 재학습 효과와 분리 못 한다.
  Liu et al. (ICLR 2019) 이 정확히 이 지점을 비판했으므로 심사에서 반드시 나온다
- **실험 2** — 없으면 §5 의 정확도 표를 못 쓴다. 가장 싸다

### 하지 않아도 되는 것

- **test-dev 제출** — 본 논문 주장은 동일 프로토콜 하 상대 비교. 범위 밖
- **50 % 계보 재확인** — 40 % 만으로 논문 성립. 부록 각주로 처리
- **멀티 NPU 재실험** — 선행 논문 결과 인용으로 충분
- **다른 검출기(YOLOv5/v8) 확장** — 선행 논문도 "compiler 지원 범위 밖"으로 처리했음
