# Channel Alignment, Not FLOPs, Governs NPU Latency in Structured Pruning of YOLOv3

초안 · IEEE Access · 2026-08-12

선행 논문 Sensors 2025, 25, 1376 의 후속이다. 선행 연구는 모델을 고정한 채 스케줄링을
최적화하여 처리량 4.81배를 얻었고, 본 논문은 모델 압축과 NPU 정렬 인식을 다룬다.

---

## Abstract

엣지 NPU 를 대상으로 한 구조적 프루닝에서 연산량 감소가 실제 지연 감소로 이어지지 않는
현상을 다룬다. YOLOv3 를 Neubla Antara NPU 에 배포한 사례에서, 프루닝 시 잔여 채널 수를
결정하는 staircase 파라미터가 연산량이 아니라 하드웨어 타일 경계인 64채널을 맞추는 역할임을
12개 모델의 실측으로 보인다. 채널을 64 배수로 정렬한 구성은 연산량이 41.8 G MACs 로 가장
많음에도 지연이 40.8 ms 로 가장 짧으며, 비정렬 구성은 37.9 G MACs 에 45.4 ms 이다. 동일한
모델을 CPU 에서 측정하면 연산량 순서가 그대로 유지되므로, 이 역전은 연산 단위 폭이 큰
가속기에 고유하다. 정렬 패딩을 반영한 지표인 padded MACs 가 raw MACs 보다 실측 지연을 잘
설명하며 피어슨 상관은 각각 0.932 와 0.879 이다. 이 결론은 1년 5개월 간격의 두 독립 측정에서
재현되며 두 측정 간 상관은 0.9988 이다. 이 원리를 반영한 40 % 프루닝 모델은 원본 대비 NPU
지연 1.30배 개선과 모델 크기 92 % 감소를 달성하면서 COCO 정확도를 유지하며, AP 는 31.51
에서 32.50 으로 변화하였다.

Index Terms — structured pruning, neural processing unit, channel alignment,
object detection, model compression, YOLOv3

## I. Introduction

경량화 연구는 통상 파라미터 수와 연산량으로 효율을 보고한다. 그러나 전용 가속기에서는 이
지표가 실제 지연을 대변하지 못한다. 가속기는 채널을 고정 폭 타일 단위로 처리하므로, 타일
경계에 맞지 않는 채널 수는 패딩되어 계산되지 않는 채널까지 자원을 점유한다.

본 논문은 Neubla Antara NPU 에 배포된 YOLOv3 압축 파이프라인을 대상으로 다음을 보인다.

첫째, staircase 는 압축률이 아니라 정렬 파라미터이다. 같은 압축률에서 staircase 를 바꾸어도
잔여 채널 수는 2 % 이내로 변하지 않으나 NPU 지연은 최대 10 % 달라진다.

둘째, padded MACs 가 raw MACs 보다 지연을 잘 설명한다. 두 독립 측정에서 동일한 결론이
재현된다.

셋째, 연산량 지표는 정반대 결론을 준다. raw MACs 가 최소인 구성이 NPU 에서는 가장 느린
구성 중 하나이다. 동일 모델을 CPU 에서 측정하면 연산량 순서가 유지되므로, 이 역전은
가속기의 정렬 제약에서 비롯된다.

넷째, 이 원리를 반영한 40 % 프루닝 모델이 NPU 지연 1.30배 개선, 크기 92 % 감소, 정확도
유지를 동시에 달성한다.

### 기여

압축률 3종과 staircase 4종을 조합한 12개 모델을 NPU 와 CPU 에서 측정하고 연산량 지표와
대조하였다.

배포 산출물로부터 프루닝 기준을 역복원하고, 이를 원본 가중치에 재적용하여 압축 파이프라인
전체를 재현하였다.

정렬 패딩을 반영한 지연 예측 지표인 padded MACs 를 제안하고 검증하였다.

## II. Related Work

구조적 프루닝은 채널 단위로 가중치를 제거하므로 희소 연산 지원 없이도 실제 가속을 얻는다는
점에서 비정형 프루닝과 구분된다. 채널 중요도 기준으로는 L1 및 L2 노름, BatchNormalization
스케일, 기울기 기반 지표가 사용된다. 다수 연구가 FLOPs 감소율로 효율을 보고하나 하드웨어
실측과의 괴리는 충분히 다루어지지 않았다.

NPU 인식 압축을 다룬 연구가 있으나 대부분 시뮬레이터나 이론 모델에 의존한다. 본 논문은
상용 NPU 실측으로 정렬 효과를 정량화한다.

YOLOv3 를 대상으로 한 프루닝 및 양자화 연구는 다수 존재하나, 평가 데이터셋이 VOC 나 커스텀
데이터로 갈리는 경우가 많고 COCO 절대값을 보고할 때 산출 조건이 기재되지 않는 경우가 많다.
본 논문은 평가 분할과 검출 예산을 해시 수준으로 고정하여 보고한다.

## III. Background

### A. 대상 모델과 계보

대상은 ONNX Model Zoo 가 배포한 yolov3-12 이며, Darknet 가중치를 ONNX 로 변환한 것이다.
정확한 파일 지문은 부록 A 에 기재하였다.

NPU 컴파일을 위해 후처리를 절단하고 BatchNormalization 을 융합한 뒤 입력 크기를
1x3x608x608 로 고정하였다. 모델은 75개 합성곱 계층에 27,069개 출력 채널을 갖는다.

### B. 대상 하드웨어

Neubla Antara NPU 를 사용하였다. 활성값 버퍼가 채널 64 단위로 정렬되며, 컴파일러 nbc 는
그룹 탐색 방식과 출력 전송 단위를 옵션으로 선택할 수 있다.

### C. 평가 프로토콜

정확도는 COCO 로 평가한다. 학습과 평가에는 YOLOv3 원 저자가 배포한 분할인 trainvalno5k
117,264장과 5k 5,000장을 사용한다. 평가에는 pycocotools 를 사용하며 score 0.001 이상,
NMS IoU 0.45, 이미지당 상위 100 검출을 제출한다. 5,000장 평가의 부트스트랩 95 % 신뢰구간
폭은 1.03 AP 이다.

NPU 지연은 보드 디버그 출력을 비활성화한 상태에서 워밍업 1회를 제외한 10회 평균으로
측정한다. 모델마다 프로세스를 새로 생성한다.

## IV. Method

### A. 프루닝 기준의 역복원

프루닝된 모델과 그 부모 가중치를 대조하여 채널 마스크를 복원하였다. 재학습 전 산출물은
부모에서 채널만 선택한 부분집합이므로 마스크가 오차 없이 결정된다.

복원된 기준은 계층별 L2 노름 상위 k 채널을 남기되, 잔여 채널 수를 staircase 의 배수로
반올림하는 것이다. residual 로 결합된 계층들은 단일 마스크를 공유한다. 40 % 구성에서 명목
압축률은 실효 37.12 % 에 해당하며 채널 수는 27,069 에서 17,021 로 감소하고, 75개 계층 중
39개가 프루닝되며 앞단 26개 계층은 유지된다.

올림이 아니라 반올림이라는 점이 중요하다. 올림이었다면 staircase 는 padded MACs 에 아무런
흔적을 남기지 못한다. staircase 8, 16, 32 는 모두 64 의 약수여서 64 의 배수는 그 자체로
staircase 의 배수이고, 따라서 목표치를 staircase 배수로 올린 값은 언제나 목표치와 그 위 첫
64 배수 사이에 놓인다. 여기에 다시 64 정렬 패딩을 적용하면 어느 staircase 를 쓰든 같은
채널 수에 도달한다.

목표치가 300채널인 계층이면 올림은 각각 304, 304, 320, 320 채널을 남기고, 패딩 후에는 넷 다
320 이 된다. 즉 올림이 규칙이라면 §V.A 표의 padded MACs 열은 압축률마다 하나의 값이어야
한다. 실측은 그렇지 않다.

12개 모델의 계층별 채널 수를 대조하면 프루닝된 123개 계층 전부가 공통 목표치 하나에
반올림을 적용한 값으로 설명되는 반면, 올림으로 설명되는 계층은 44개, 36 % 에 그친다. 예컨대 512채널 계층에서 staircase 8 은
328채널을, staircase 64 는 320채널을 남긴다. 올림이라면 staircase 가 클수록 잔여 채널이
단조증가해야 하므로 이 역전은 성립할 수 없으며, 50 % 구성에서 이러한 비단조 계층이 75개 중
32개이다.

반올림은 목표치보다 최대 staircase 의 절반만큼 아래로 내려갈 수 있다. staircase 8 은 4채널,
staircase 64 는 32채널이므로 네 모델은 서로 다른 64 경계 구간에 착지한다. 이것이 다음 절에서
같은 압축률 안의 padded MACs 가 staircase 에 따라 갈라지는 원인이다.

이 마스크를 원본 가중치에 재적용하여 프루닝 단계를 재현하였다.

### B. Padded MACs

NPU 가 채널을 64 단위로 처리한다는 가정에서, 실제 비용은 raw MACs 가 아니라 패딩된 채널까지
포함한 값이어야 한다. 계층별 입력 채널 수와 출력 채널 수를 각각 64 의 배수로 올림한 뒤
연산량을 계산한다. 출력 해상도는 계층마다 그래프에서 확정한다. 같은 방식을 원본에 적용하면
70.35 G MACs 로, Darknet 이 공표한 416 입력 65.86 BFLOPs 의 608 환산치 70.34 G 와 일치한다.

## V. Staircase and Hardware Alignment

### A. 실측

압축률 3종과 staircase 4종을 조합한 12개 모델을 측정하였다. 동일한 양자화 설정과 동일한
컴파일 옵션을 적용하였다.

| ratio | sc | raw MACs [G] | padded MACs [G] | 64배수 conv | NPU [ms] |
|---:|---:|---:|---:|---:|---:|
| 10 % | 8 | 65.6 | 84.2 | 44/75 | 54.3 |
| | 16 | 65.7 | 84.2 | 46/75 | 54.2 |
| | 32 | 66.5 | 84.2 | 60/75 | 53.7 |
| | 64 | 66.4 | 83.3 | 70/75 | 53.7 |
| 30 % | 8 | 53.9 | 74.8 | 25/75 | 50.3 |
| | 16 | 53.7 | 74.7 | 34/75 | 48.8 |
| | 32 | 54.6 | 72.4 | 58/75 | 45.9 |
| | 64 | 54.7 | 71.6 | 70/75 | 46.2 |
| 50 % | 8 | 38.0 | 61.7 | 18/75 | 45.2 |
| | 16 | 37.9 | 59.9 | 32/75 | 45.4 |
| | 32 | 38.7 | 58.9 | 52/75 | 45.5 |
| | 64 | 41.8 | 58.7 | 70/75 | 40.8 |

50 % 구간에서 staircase 64 는 raw MACs 가 가장 많음에도 가장 빠르다. 연산량은 sc8 대비
10 % 많으나 지연은 10 % 적다. padded MACs 로 보면 순서가 뒤집혀 61.7 G 에서 58.7 G 로
감소한다.

같은 압축률 안에서 padded MACs 가 갈리는 정도는 staircase 별 해가 서로 다른 64 경계 구간에
착지한 계층 수를 따른다. 10 % 에서는 그런 계층이 7개뿐이고 staircase 8, 16, 32 는 75개 계층
전부가 같은 구간에 들어가 padded MACs 가 84.2 G 로 완전히 일치한다. 30 % 에서 19개, 50 %
에서 22개로 늘면서 값이 벌어진다. 50 % 구성에서 패딩이 채우는, 계산되지 않는 채널은
staircase 8 이 1,755개, staircase 64 가 67개이다.

### B. 지표 비교

| 지표 | 본 연구 2026-08 | 원 측정 2025-03 |
|---|---:|---:|
| raw MACs | 0.8787 | 0.8778 |
| padded MACs | 0.9315 | 0.9319 |
| 활성값 raw | 0.8214 | 0.8223 |
| 활성값 padded | 0.9105 | 0.9126 |

두 측정 간 상관은 0.9988 이다. 1년 5개월 간격, 서로 다른 양자화 설정과 드라이버 버전에서
12점의 상대 구조가 재현된다.

### C. CPU 와의 대조

정렬 효과가 가속기 고유인지 확인하기 위해 동일한 12개 모델을 CPU 에서도 측정하였다.
CPU 측정에는 ONNX Runtime CPU 실행 공급자를 사용하였다.

50 % 압축률 구간의 결과는 다음과 같다.

| sc | raw MACs [G] | CPU [ms] | NPU [ms] |
|---:|---:|---:|---:|
| 8 | 38.0 | 129.7 | 45.2 |
| 16 | 37.9 | 133.1 | 45.4 |
| 32 | 38.7 | 134.8 | 45.5 |
| 64 | 41.8 | 145.6 | 40.8 |

CPU 에서는 연산량이 가장 많은 staircase 64 가 가장 느리다. NPU 에서는 같은 구성이 가장
빠르다. 12개 모델 전체에서 raw MACs 와의 상관은 CPU 가 0.9438, NPU 가
0.8787 이다.

CPU 의 SIMD 폭은 float32 기준 최대 16 이므로 정렬 단위가 NPU 의 64 보다 훨씬 작고,
경계에 맞지 않는 잔여 채널은 스칼라 경로로 처리된다. 반면 NPU 는 활성값 버퍼 자체가
64채널 폭으로 할당되므로 사용되지 않는 채널이 자원을 계속 점유한다. 정렬 효과는 연산
단위 폭이 크고 유연성이 제한된 가속기에서 나타나는 현상이다.

### D. 바이너리 크기

정렬은 컴파일 산출물 크기에도 나타난다. 압축률이 높을수록 정렬 효과가 커진다.

| ratio | sc8 | sc16 | sc32 | sc64 | 감소 |
|---|---:|---:|---:|---:|---:|
| 10 % | 151 MB | 151 MB | 149 MB | 149 MB | 1 % |
| 30 % | 132 MB | 132 MB | 124 MB | 124 MB | 6 % |
| 50 % | 112 MB | 110 MB | 108 MB | 105 MB | 6 % |

## VI. Compression Results

### A. 파이프라인

복원한 마스크를 원본 Darknet 가중치에 적용하고, 원 저자 분할인 trainvalno5k 117,264장으로
10 에포크 재학습한 뒤 양자화와 컴파일을 수행하였다.

### B. NPU 지연

네 모델을 동일한 실행에서 측정하였다.

| 모델 | NPU [ms] | 가속 |
|---|---:|---:|
| 원본 | 58.4 | 1.00 |
| 배포된 40 % 프루닝 | 45.4 | 1.29 |
| 배포된 50 % 프루닝 | 43.5 | 1.34 |
| 본 연구 40 % 프루닝 및 재학습 | 44.6 | 1.31 |

본 연구의 재현본이 배포본과 1 ms 이내로 일치한다. 40 % 에서 50 % 로 압축률을 높이면 지연은
1.9 ms 더 줄어드는 데 그친다.

### C. 정확도

COCO 5k 5,000장 전수, 표준 프로토콜 기준이다.

| 모델 | AP | AP50 | AP75 |
|---|---:|---:|---:|
| 원본 | 31.51 | 56.18 | 31.93 |
| 프루닝 직후, 재학습 없음 | 0.08 | 0.30 | 0.01 |
| 프루닝 및 재학습 10 에포크 | 32.50 | 52.30 | 35.20 |

원본과 동일한 학습 데이터를 사용하므로 학습량 차이에 의한 교란이 없다. 부트스트랩 95 %
신뢰구간 폭이 1.03 AP 이므로 정확도는 유지된 것으로 판단한다.

구조적 프루닝은 재학습 없이는 모델을 완전히 파괴한다. AP 는 0.08 에 그치고 AP75 는 0.01 로
사실상 검출에 실패한다. 성능의 거의 전부를 재학습이 만든다.

### D. 모델 크기

fp32 원본 248 MB 가 uint8 프루닝본 20.6 MB 로 감소하여 92 % 축소된다. NPU 바이너리는
166.8 MB 에서 113 MB 로 감소한다.

### E. 컴파일 옵션

50 % 및 staircase 64 구성에서 컴파일 옵션을 lw 에서 egs 로 변경하면 지연이 43.5 ms 에서
22.3 ms 로 감소하여 1.88배 개선된다. 바이너리는 105 MB 에서 92 MB 로 감소한다. 컴파일
옵션은 정렬과 독립적으로 추가 이득을 제공한다.

---

## VII. Discussion

연산량 지표만으로 압축 설계를 최적화하면 하드웨어에서 손해를 볼 수 있다. 본 사례에서 raw
MACs 가 최소인 구성은 실제로 가장 느린 구성 중 하나였다. 설계 시점에 하드웨어 타일 폭을
알고 있다면, 채널 수를 타일 폭의 배수로 강제하는 것이 연산량을 다소 늘리더라도 유리하다.

정렬은 활성값 버퍼 점유에도 작용한다. 32채널 출력이 64채널 폭 버퍼를 점유하므로, 프루닝으로
줄인 채널이 메모리 절감으로 곧바로 이어지지 않는다.

---

## VIII. Limitations

30 % 구간에서 staircase 32 가 staircase 64 보다 근소하게 빠르다. 45.9 ms 와 46.2 ms 이다.
이 역전은 두 독립 측정 모두에서 재현되므로 측정 잡음이 아니며, 정렬이 지배적이지만 유일한
요인은 아님을 시사한다. 메모리 대역폭, 계층별 타일링, 명령어 스케줄링이 잔여 요인으로 남는다.

staircase 별 정확도를 측정하지 않았다. 조합마다 재학습이 필요하기 때문이다. 같은 압축률
안에서 잔여 채널 수가 2 % 이내로 동일하므로 모델 용량은 사실상 같으나 실증되지는 않았다.

대조군으로 CPU 를 사용하였으나 GPU 는 측정하지 않았다. 정렬 폭 64 는 Antara 고유값이며
타 NPU 로의 일반화는 검증되지 않았다.

비정렬 모델 일부에서 egs 컴파일이 실패하였으나, 해당 모델들이 재학습 전 상태로 유효한
출력을 내지 못하여 원인을 분리하지 못하였다.

절대 정확도의 외부 비교를 위해서는 test-dev 제출이 필요하나, 본 연구의 주장은 동일 프로토콜
하의 상대 비교이므로 범위 밖이다.

---

## IX. Conclusion

엣지 NPU 를 대상으로 한 구조적 프루닝에서 연산량 지표는 실제 지연을 대변하지 못한다. 채널을
하드웨어 타일 폭의 배수로 정렬하면 연산량이 늘어남에도 지연이 줄어들며, 정렬 패딩을 반영한
padded MACs 가 실측을 더 잘 설명한다. 이 원리를 반영한 40 % 프루닝 모델은 NPU 지연 1.30배
개선과 모델 크기 92 % 감소를 정확도 손실 없이 달성하였다.
